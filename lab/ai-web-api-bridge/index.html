LAB / PUBLIC RESEARCH NOTE 001

Web版AIを
APIとして使えるか？

ClaudeやGeminiのWebチャットを、APIキーを要求するアプリから利用したい。既存のオープンソース実装と、実用・規約上の境界を公開情報から整理しました。

2026年11月4日 調査版 v0.1 ｜ 対象：Claude Web / Gemini Web

調査の範囲GitHubの公開説明・公式ヘルプ・利用規約に基づくデスク調査です。各ツールのソースコード全体の監査、Macでの起動、ログイン、API応答の実機検証は実施していません。ここでの「対応」は開発元の自己申告を含み、動作を保証しません。規約に反する利用を推奨するものでもありません。

暫定結論：Web画面や非公開通信をOpenAI互換APIへ変換する非公式OSSは複数存在する。しかし「個人のWeb利用枠を任意のアプリから追加API料金なしに使う」ことが、公式に許可され、安定稼働するとは確認できない。特にClaudeでは第三者ツールへのサブスクリプション枠流用に明示的な制約がある。

なぜ調べるのか

ノートアプリや個人開発ツールには、AI機能の利用にAPIキーと従量課金を要求するものがある。一方、普段はWeb版のチャットAIを使っている。「Web版で使えるAIを、API対応アプリからも呼び出せないか」という疑問から出発した。

ClaudeとGeminiでは何が違う？

Claude Web

技術的な非公式ブリッジはある。しかしAnthropic公式ヘルプは、サブスクリプションの利用枠が主に自社のネイティブアプリ向けであると説明し、第三者のトラフィックをサブスクリプション枠へ流すことや、クライアントの身元を偽ることを禁止している。個人利用でも自動的に例外にはならない。Anthropic公式の認証方針

Gemini Web

非公式API化の実装例は複数ある。ただし、Googleの一般利用規約には、機械可読な指示に反した自動アクセス、保護機構の回避、一定のリバースエンジニアリング等への制限がある。今回、Gemini Webの利用枠を汎用APIへ自由に転用する公式許可は確認できなかった。Google利用規約

アプリ側の制約もある

APIキー対応と書かれていても、必ずしも接続先URLを変更できるわけではない。外部アプリがOpenAI互換のBase URLを指定できるならローカルブリッジに接続しやすい。一方、公式APIのURLが固定されたアプリでは、アプリ側の改修が必要になる。さらに、ブラウザアプリではCORSやContent Security Policyも確認する必要がある。

個人利用でも注意したいこと

  • 規約：非公開プロトコルやWeb画面の自動操作は、実装が存在しても利用許可を意味しない。
  • アカウント：認証Cookie・セッショントークンを第三者製のソフトへ渡すと、アカウント乗っ取り等の危険がある。
  • 機能互換：テキスト応答ができても、ストリーミング・画像・ツール呼び出し・モデル指定まで一致するとは限らない。
  • 安定性：Web UIや内部APIの変更、レート制限、ログイン認証の変更で停止し得る。
  • 料金：Webプランの利用枠と公式APIの従量課金は通常別物。「API無料化」を保証する仕組みではない。

現時点の評価と次の検証項目

検証テーマ現状次に確認すること
Web版 → OpenAI互換APIの変換公開実装ありAPI仕様・エラー・モデル指定の互換性
Gemini Web接続実機未検証メンテナンス状況と公式な利用許諾
Claude Web接続規約上の制約正式に認可された代替接続方法
TakeMyNote等への接続実機未検証Base URL変更、CORS・CSP、アプリ改修範囲
個人利用での長期安定運用未確認公式対応状況、セキュリティ、保守体制

研究方針：「API変換の技術」と「外部AIへの接続許可」は切り分けて検討する。公開実装の比較を継続し、将来公式に利用が認められる接続方式にも置き換えられる構造を目指す。
